# 이어서 작업하기 — 여기부터 읽기

최종 갱신: 2026-10-08. 다른 컴퓨터나 새 AI 대화에서 이어갈 때 이 파일을 먼저 읽는다. 세부 규칙과 수치 근거는 [HANDOFF.md](HANDOFF.md)의 맨 아래 v0.5와 v0.6 절에 있다. 그 앞의 v0.4 이하는 과거 기록이다.

## 1. 새 컴퓨터에서 시작

```bash
git clone https://github.com/99jungwon/baseball-career.git
cd baseball-career
node server.js
```

- 브라우저에서 http://localhost:4173 을 연다. 서버는 그 터미널에서 Ctrl+C로 끈다.
- 서버를 켜둔 채 코드를 고치면 새로고침만으로 반영된다.
- 테스트는 `node tests/engine.test.js`와 `node tests/league.test.js`로 돌린다.
- Node.js만 있으면 된다. npm 설치나 빌드는 없다.
- 공개 배포판: https://99jungwon.github.io/baseball-career/ . GitHub Pages가 main 브랜치의 루트를 배포하며, push하면 1~2분 뒤 반영된다.
- 이미 클론한 컴퓨터에서는 작업 전에 `git pull`로 최신 코드를 받는다.

## 2. 작업 규칙 (사용자와 합의)

- **커밋과 push는 사용자가 직접 한다.** GitHub 관리를 연습하는 중이다. AI는 작업이 끝나면 바뀐 파일과 커밋 메시지만 제안한다.
- 한국어로 편하게 대화한다. 계획만 늘어놓기보다 실제로 동작하는 결과를 선호한다.
- **사용자의 브라우저 저장을 테스트하느라 지우거나 진행시키지 않는다.** 사용자 PC의 진행 선수(김루키)는 localhost:4173에 있다. 검증은 별도 포트(4174, 4175)에서 한다. 저장은 주소와 기기별로 따로 잡힌다.
- 폰 배포판의 저장과 PC 저장은 별개다. 이전·가져오기 기능은 아직 없다.
- index.html은 루트에 두고 상대경로를 유지한다(Pages 배포 조건).
- 밸런스를 바꾸면 시뮬레이션으로 수치를 확인한다. 아래 4번을 참고한다.

## 3. 폴더 구조

```
index.html, server.js, README.md   실행에 필요한 것만 루트에
js/      engine(규칙) · league(KBO 가상 리그) · collection(은퇴 보관함)
         training-games(미니게임) · career-views · app(화면)
css/     style.css
tests/   engine.test.js, league.test.js
docs/    NEXT_SESSION.md(이 파일), HANDOFF.md(상세 인계), VERIFICATION.md
docs/screenshots/   검증 캡처
```

index.html의 스크립트 로딩 순서는 league → collection → engine → training-games → career-views → app이다.

## 4. 2026-10-08에 한 일

1. **플레이테스트로 밸런스 문제 발견.** 자동 진행 180커리어 전원이 47세 은퇴, 통산 약 3,700안타, 수상 48개였다. 능력치가 25~30세에 전부 100이 됐다.
2. **v0.5 잠재력 시스템.** 능력별 숨은 한계, 다시 뽑기(첫 훈련 전), 노력 보정(저잠재일수록 한계 돌파 폭이 넓음), 각성(수상 시즌), 개인별 노화, 능력 기반 출전, 계약 기준 조정.
   - 결과: 은퇴 중앙값 36세, 통산 안타 중앙값 약 1,960, 골든글러브 53~58%. 고잠재(약 2%)는 골든글러브 100%다.
3. **폴더 정리**(js/css/tests/docs), **GitHub 업로드**, 저장소 public 전환 후 **GitHub Pages 배포**.
4. **v0.6 반복 줄이기.** 시즌 훈련 계획, "중요한 순간까지 진행", 시즌 2회 특별 훈련(미니게임 보상 약 2배), 9월 타이틀 경쟁 선택.
   - 결과: 미니게임을 빼면 시즌당 클릭이 약 40번에서 약 8번으로 줄었다.

시뮬레이션 스크립트는 저장소에 없다. 다시 측정하려면 `E.create(...,{school:true})`로 여러 시드를 만들고 `E.autoSeason` + `E.offseason`으로 은퇴까지 돌린 뒤 통산 안타, 은퇴 나이, 수상을 집계하면 된다.

## 5. 다음 할 일 후보 (우선순위 미정, 사용자와 정하기)

- 사용자가 폰으로 몇 시즌 플레이한 뒤 체감 피드백 반영: 성장 속도, 잠재력 체감, 자동 진행 빈도.
- 자동 진행과 직접 육성의 성과 차이가 작다(골든글러브 58% vs 67%). 특별 훈련이나 선택의 영향 확대를 검토.
- 오프시즌 화면에서 다음 시즌 계획 바꾸기, 자동 진행 요약에 능력치 변화 표시.
- 타이틀 경쟁 빈도가 낮다(시즌당 약 10%). 포스트시즌 진출 경쟁 사건 추가를 검토.
- 이름 입력칸에 "김루키"가 실제 값으로 미리 들어가 있어서, 입력하면 뒤에 이어 붙는 문제(아직 안 고침).
- 기록 JSON 가져오기(기기 간 이동의 임시 방법).
- 장기 과제: 선수 DNA, 아이콘·시각 강화, 로그인 + 클라우드 저장(Supabase 후보), 투수.
